# Account Security

## Overview

Account security protects customer accounts, personal information, billing information, and application access.

Customers are responsible for keeping their login credentials secure.

Support agents must follow security procedures when handling account-related requests.

## Passwords

Customers should use a strong, unique password for their account.

Customers should never share their password with support agents.

If a customer forgets their password, they should use the password reset process available on the sign-in page.

Password reset links may expire for security reasons.

If a password reset link has expired, the customer should request a new reset link.

## Password Changes

Customers can change their password from the account security settings.

If a customer cannot change their password because of an error, support can investigate the issue.

Support agents must never request the customer's current password or new password.

## Account Lockouts

An account may be temporarily locked after multiple unsuccessful login attempts.

Account lockouts are intended to protect the account from unauthorized access.

Customers who are locked out should follow the account recovery process or contact support.

Support may verify account ownership before restoring access.

## Two-Factor Authentication

Two-factor authentication provides an additional layer of account security.

When enabled, customers may be required to provide a verification code during login.

Customers should never share authentication codes with support agents.

If a verification code is not accepted, the customer should:

1. Request a new verification code.
2. Use the most recently generated code.
3. Check that the code has not expired.
4. Retry the authentication process.

If the problem continues, support should investigate the authentication issue.

## New Device Verification

A customer may be asked to verify their identity when signing in from a new device.

Additional verification helps protect the account from unauthorized access.

Customers should complete the verification process using the security method associated with their account.

## Suspicious Login Activity

Customers should contact support if they receive a security notification for a login they do not recognize.

Support may review account activity and determine whether additional security actions are required.

If a customer suspects unauthorized access, they should change their password as soon as possible.

## Unauthorized Transactions

Customers should report transactions they do not recognize.

Support should investigate suspicious transactions using the billing and transaction records.

A suspicious transaction may require additional security review.

Customers should never provide complete payment credentials through support conversations.

## Sensitive Information

Support agents must never ask customers to provide:

- Account passwords
- Authentication codes
- Full payment card numbers
- CVV or security codes
- Private API keys
- Access tokens
- Recovery codes
- Other authentication secrets

If sensitive credentials are accidentally shared in a support conversation, the information should be treated as compromised and appropriate security procedures should be followed.

## Account Email Changes

Customers may request to change the email address associated with their account.

Email changes may require verification to confirm account ownership.

Support should follow the account verification procedure before making sensitive account changes.

## Account Deletion

Customers may request permanent account deletion.

Before processing account deletion, support should verify that the requester is authorized to make the request.

Account deletion may be permanent and should not be performed accidentally.

Customers should understand the consequences of deleting their account before confirming the request.

## Security Incidents

Security-related issues should be handled with higher priority than ordinary product questions.

Examples include:

- Unauthorized login
- Suspicious transaction
- Account takeover concern
- Lost authentication device
- Compromised credentials
- Repeated unauthorized access attempts

Security incidents may require escalation to the appropriate security team.

## Customer-Specific Security Information

This document describes general security procedures.

It does not contain private customer security information.

Questions such as:

> "Is my account locked?"

> "Was there a login from another device?"

> "Did my account have a suspicious transaction?"

must be answered using authorized customer-specific systems and tools.

Support agents must not guess or infer security events.
