# Refunds

## Overview

Refunds return money to a customer after an eligible transaction has been reversed or partially reversed.

A refund is associated with an original payment transaction.

Refund information may include:

- Original transaction
- Refund amount
- Refund status
- Refund date
- Original payment method

## Refund Statuses

A transaction may have one of the following refund-related states:

- Refunded
- Partially refunded
- Pending refund

A refunded transaction means the full applicable amount has been returned.

A partially refunded transaction means only part of the original transaction amount has been returned.

A pending refund means the refund process has been initiated or is still being processed.

## Refund Timing

After a refund is processed, the funds may not appear immediately in the customer's account.

The time required for the refund to appear depends on the payment provider and payment method.

Customers should allow additional processing time before reporting that a processed refund has not arrived.

If a refund remains unavailable after the expected processing period, support should investigate the transaction.

## Full Refunds

A full refund means the applicable transaction amount has been returned to the customer.

The support agent should verify the original transaction and refund record before confirming the refund.

A customer should not be told that a refund was completed unless the transaction data confirms the refund status.

## Partial Refunds

A partial refund means only part of the original transaction amount was returned.

A customer may ask why the refunded amount is different from the original transaction amount.

For these questions, support should:

1. Retrieve the original transaction.
2. Retrieve the refund amount.
3. Compare the original transaction amount with the refund amount.
4. Explain the difference using the available transaction information.
5. Escalate the issue if the refund amount appears incorrect.

## Refund Requests

A customer asking about a refund does not automatically mean that a refund has been issued.

The support agent must distinguish between:

- A refund request
- An approved refund
- A processed refund
- A completed refund
- A partial refund

The agent must not claim that money has been refunded unless the transaction records confirm it.

## Refund to Original Payment Method

Refunds are normally associated with the original payment transaction and payment method.

Customers should generally expect the refund to be returned through the applicable payment channel.

If the customer cannot locate the refund, support should first verify the transaction and refund records.

## Refund Investigation

When investigating a refund issue, support should check:

- Customer ID
- Original transaction ID
- Original transaction amount
- Transaction status
- Refund amount
- Refund timestamp
- Refund status
- Payment method

Customer-specific refund information must be retrieved from the billing transaction system.

## Refund and Subscription Cancellation

Cancelling a subscription does not automatically create a refund.

Subscription cancellation and transaction refunds are separate processes.

A customer may cancel a subscription without receiving a refund for a previously completed billing transaction.

If a customer asks whether a cancellation resulted in a refund, support must check the transaction records.

## Multiple Refunds

If multiple transactions exist for the same customer, support must identify the correct transaction before discussing a refund.

The agent should not assume that the most recent transaction is the transaction referenced by the customer without checking the available information.

## Important Support Rule

The knowledge base explains general refund behavior.

It does not contain customer-specific refund information.

For questions such as:

> "Was my payment refunded?"

> "How much was I refunded?"

> "When was my refund processed?"

the support agent must retrieve the customer's transaction information from the billing system.

The agent must never invent a refund amount, refund date, or refund status.
